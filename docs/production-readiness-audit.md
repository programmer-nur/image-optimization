## A. Overall Status

## **NOT READY**

Not for lack of engineering quality — the core is unusually well-built (see §E confirmations) — but because the audit found **four CRITICAL defects**, two of which are genuine bugs in code paths that destroy data or unbounded-amplify cost, and two of which make the documented bootstrap physically fail. Additionally: the system has never executed against AWS, and multi-tenancy (commissioned for the owner's multi-app go-live intent) does not exist yet. Path to **PRODUCTION CANDIDATE**: fix C1–C4 + H5 (pre-cache grammar fixes), deploy to staging, burn down 9.15/12.9/13.7/14.7.

## B. Critical Issues (deployment-unsafe)

**C1 — Unbounded variant space via direct `/derived/…` viewer URLs.** The edge normalizer only rewrites `/i/*` and passes every other path through (`infra/cloudfront/normalize.template.js:296-300`); the single CloudFront default behavior routes all paths to the S3→generator failover group (`infra/cdk/lib/cdn-stack.ts:141-153`); and the generator's `parseVariantName` accepts **any positive-integer** width/height — no ladder check (`packages/core/src/canonical-key.ts:174-178`, acceptance codified in `canonical-key.test.ts:175`). Since `{id, version, epoch}` are visible in every public URL, an unauthenticated client can sweep `w641, w642, …` — each minting one Sharp invocation, one permanent S3 object, one permanent cache entry, and a bookkeeping row tied to a live version that maintenance will never reclaim. This defeats the bucketing invariant the entire cost model rests on, and `infra/cdk/lib/waf.ts:11-14` exempts the delivery plane from rate limiting on the now-false premise that the variant space is structurally bounded.
_Fix:_ edge returns 400 for viewer URIs beginning `/derived/`; generator validates `width ∈ LADDER` (or sub-rung source-capped) and `height` equals the quantized-ratio derivation before rendering. Both, not either.

**C2 — Superseded-version expiry ages from the wrong timestamp; originals destroyed without their grace window.** `packages/db/src/asset-repository.ts:383-403` filters `createdAt < cutoff` on the superseded version's **own** creation date — its own docstring (:377-382) and `specs/storage-lifecycle/spec.md:65-75` say the window must run from the _supersession_ moment. A source that was current for longer than `supersededRetentionDays` (default 30) becomes deletable on the first maintenance run after replacement: replaced yesterday → original, master, all derivatives, and rows irreversibly deleted today (`apps/maintenance/src/maintenance.ts:168-201`), and consumer HTML caching the old URLs breaks immediately instead of after 30 days. The integration test creates both versions at the same instant and passes under both semantics (`maintenance.integration.test.ts:148-162`).
_Fix:_ age off the _superseding_ version's `createdAt` (or add `supersededAt`); add a staggered-timestamps test.

**C3 — The database migration task cannot succeed as wired; bootstrap dead-ends.** The migration ECS task runs `node node_modules/prisma/build/index.js migrate deploy` (`infra/cdk/lib/compute-stack.ts:465`), but: `prisma` is a devDependency pruned by the `--prod` install the runtime image copies (`packages/db/package.json:36`, `apps/api/Dockerfile:49-61`); the container receives `DB_*` parts but never `DATABASE_URL`, which the Prisma CLI requires (`packages/db/prisma.config.ts:16`); and the runtime image contains no `schema.prisma`, `prisma.config.ts`, or `prisma/migrations`. The DB sits in `PRIVATE_ISOLATED` subnets with no documented alternative access path, so bootstrap step 6 fails with no workaround.
_Fix:_ migration-capable image (promote `prisma` to a prod dep of `@imgopt/db`, copy `packages/db/prisma*` into the runtime stage, compose `DATABASE_URL` in an entrypoint).

**C4 — The control-plane API serves plain HTTP in every environment.** `apiCertificate` exists on `ComputeStackProps` (`compute-stack.ts:54`) but is never passed by `bin/app.ts`; no regional ACM certificate is created anywhere; `config.apiHost` is consumed by nothing. The ALB listener is always HTTP:80 (`compute-stack.ts:375-380`) with no redirect — the network-stack comment claiming "80 answered only to redirect" (`network-stack.ts:93-94`) is false as wired. `x-api-key` credentials and upload payloads would cross the internet in cleartext.
_Fix:_ regional DNS-validated cert for `apiHost`, wire through `bin/app.ts`, HTTPS listener + 80→443 redirect, fail synth in production when absent.

## C. High / Medium / Low Issues

### HIGH

**H1 — Signed private delivery is structurally broken on its positive path.** The trusted-key-group behavior on `/p/*` exists and correctly denies unsigned requests (`cdn-stack.ts:158-178`), but the edge function only rewrites `/i/*` (`normalize.generated.js:26,196`), signed URLs are minted under `/p/…` (`signed-url.service.ts:57`), the bucket grant covers only `derived/*`, and the generator rejects non-`derived` paths — so a **correctly signed** URL 403s at S3, fails over, and 400s at the generator, with unbucketed cache keys along the way. Task 11.6 is checked; the feature has never worked end to end. _Fix:_ teach the normalizer the `/p` prefix (with conformance vectors) and rewrite into the same `derived/` key space.

**H2 — The cache-hit-rate alarm can never receive data.** `CacheHitRate` is a CloudFront _additional metric_ that publishes only after a monitoring subscription is enabled; no `CfnMonitoringSubscription` exists in `infra/` (`observability-stack.ts:205-228`). With `treatMissingData: NOT_BREACHING` it reads healthy forever — the silent-disarm failure mode this stack's own comments warn about, on one of the two normalization-drift detectors. Also pinned `region: 'us-east-1'`. _Fix:_ add the subscription in the CDN stack.

**H3 — Focal-point cropping is a documented no-op end to end.** `crop=focal` renders as `centre` (`render.ts:58-63`); nothing on any generation path reads `asset.focalPoint`; reprocess re-enqueues the same version and the optimizer skips existing keys (`optimizer.ts:201-204`), so PATCHing a focal point changes a DB column and nothing else — while `gfocal` mints keys byte-identical to the elided-center key (fragmentation). `specs/image-asset-registry/spec.md:73-75` (version bump + re-derivation) is contradicted, and that spec also self-contradicts (:102). _Fix (decision required):_ implement focal-aware generation (conflicts with "generator never reads the DB" — needs a design decision) or remove `focal` from the public grammar until it exists.

**H4 — Alarm coverage gaps present real failures as healthy.** `generatorFunctionName`/`optimizerFunctionName` props are accepted and never used (`observability-stack.ts:32-33`): there are **no** `AWS/Lambda` Errors/Throttles/Duration alarms at all. Generator throttling — the designed fail-fast under a miss storm — is invisible (throttled invocations never run, so they emit no custom metric). Maintenance failures are fully silent (no alarm, and `apps/maintenance` emits no metrics), so reclamation can stop for months while storage grows. No CloudFront `5xxErrorRate` alarm. _Fix:_ Throttles>0 (generator), Errors (all three), maintenance-ran heartbeat, CF 5xx.

**H5 — Two grammar defects fragment the cache and are epoch-class once cached — fix BEFORE anything is ever cached.** (a) `fit=pad` and `fit=contain` produce byte-identical output but distinct keys (`render.ts:68-72`); (b) gravity survives in the key for `fit=outside`, which sharp never crops — up to 8× fragmentation per outside variant (`effects.ts:23`, `transform-spec.ts:240-241`). Both are cheap one-line fixes today and an encoder-epoch event after first production cache. _Fix now:_ alias `pad`→`contain` at parse; remove `outside` from `CROPPING_FITS`; regenerate the edge function; extend vectors.

**H6 — Originals have no storage-level safety net.** `versioned: false` (`storage-stack.ts:44`), no replication, no AWS Backup — combined with the fact that _two_ roles can delete under `original/*` (maintenance, plus the API task role backing `DELETE /v1/images/:id` — `compute-stack.ts:441`, contradicting the documented single-role claim, now corrected in CLAUDE.md) and with C2's bug class, a single defect permanently destroys irreplaceable sources. "Write-once" is enforced only by code. _Fix:_ enable versioning with noncurrent-version expiry (cost-bounded), at least for `original/`.

## E. End-to-End Flow Verification

**Executed in this audit session** (sandbox: Node 22, no Docker — integration tests run in CI with service containers, not runnable here): see §E.1 results below.

**Upload flow** (Client → NestJS → session → S3 original → queue → Lambda+Sharp → optimized S3): traced and test-verified. Presigned POST is constrained (`content-length-range`, exact content-type, ≤1h expiry — `s3.ts:336-344`); `complete` triggers magic-byte sniff → malware gate → staging→original copy (`upload.service.ts:175-241`); promotion enqueues the warm set, and a failed enqueue never fails the upload (`upload.service.ts:255-282` — but see M2); the optimizer renders warm derivatives with `putIfAbsent` (`IfNoneMatch:'*'`, 412→lost-race-benign — `s3.ts:181-211`), writes LQIP/metadata, flips `stored→ready` via a legal-transition guard (`status.ts:31-44`); duplicate SQS delivery is idempotent (exists-skip + conditional write + upsert — verified `optimizer.integration.test.ts:169`); double `complete` → 409 sequential, composite-PK loser rollback concurrent (`upload.service.ts:141-143,262-267`, `schema.prisma:99`). **Note:** the S3→Event→SQS leg in the original diagram is deliberately API-enqueued instead (recorded design); S3 events are used for the GuardDuty malware path only.

**Delivery flow** (CDN request → normalization → S3 → miss failover → generation → persist → serve): traced and conformance-verified. Edge rewrites `/i/{id}/{version}/…?w=…` to the canonical `derived/…` key, drops the query string (`normalize.template.js:311-314`); cache policy is path-only (`cdn-stack.ts:83-94`); S3 miss (403/404) fails over to the OAC-protected, IAM-authed generator Function URL (`cdn-stack.ts:105-120`, `compute-stack.ts:191-195`); generator re-derives the key from the path alone, validates the epoch, renders deterministically, persists **before** responding, swallows bookkeeping failure (`generator.ts:96-284`); next request is an S3 hit. Dogpile on one key: deterministic output + conditional write + redundant-write metric — safe. Edge/core agreement: 200+ shared conformance vectors replayed against both implementations plus a byte-identity gate on the committed artifact, enforced in CI (`conformance.test.mjs:70-104`, `ci.yml:51-60`). **The flow holds for well-formed `/i/` URLs; C1 documents the unnormalized bypass.**

## G. Performance Review

No observed numbers exist — nothing has run on AWS; 13.7's load-test script is written and never executed. What can be said from code and the D16 model: delivery-plane latency is dominated by CloudFront hit ratio (path-only cache key, immutable URLs, and error-caching design are all correct for it — but H2 means hit-rate regressions are currently invisible, and C1/H5/H3 all _manufacture_ fragmentation); first-request latency = generator cold start + Sharp render at 3008MB (a labelled guess pending 14.7 power tuning); upload initiation is a presign + two DB writes (no S3 round-trip on the hot path); API list queries are indexed cursor pagination (bounded, `asset-repository.ts:51-56`); queue throughput is batch-5 with partial-batch ack — fine — but M3 (unbounded consumer concurrency vs micro Postgres) is the first real throughput ceiling, and M4 causes duplicate work under sustained backlog. Optimization opportunities, in value order: fix C1/H5 (protect the hit ratio), enable the monitoring subscription (H2), run 14.7 (memory/cost curve), add `maxConcurrency` (M3), Origin Shield on the fallback origin (L7).

## H. Security Review

**Sound and verified:** global fail-closed auth with two public health routes; timing-safe key verification with pre-compare revocation check; 256-bit random secrets with SHA-256 at-rest (salt unnecessary at that entropy — doc wording fixed); pino redaction covers keys/presign material; presigned POST pins size range, exact content-type, bounded expiry; magic-byte validation precedes promotion, SVG refused by default, decompression-bomb guard on the validation and render paths; delivered bytes are always re-encoded (polyglot defense holds structurally — CloudFront can only read `derived/*`); generator Function URL is IAM-authed behind OAC, not publicly invokable; IAM is prefix-scoped with no resource wildcards; DB credentials generated into Secrets Manager and injected as ECS secrets — no plaintext secrets found anywhere; buckets block all public access, enforce SSL, deny unencrypted writes; regional WAF rate-limits the control plane (300 mutating / 3000 overall per 5-min IP).

**Broken or gapped:** C4 (API is plain HTTP — credentials in cleartext: the single worst security finding); C1 (unauthenticated delivery-plane cost/storage amplification, and the WAF explicitly exempts the delivery plane on the false bounded-space premise); H1 (private delivery broken on the positive path — currently fails safe, denying everyone); H6 + the two-role originals-delete surface; M8 (403-vs-429 contract); L4 (permissionless reads for any valid key); L5 (first-request failure >6MB derivative); L6 (no access logs for abuse attribution); M16 (SVG flag is a trap). SSRF/path traversal: checked and clean — the generator re-serializes and byte-compares parsed keys, rejects traversal (`canonical-key.test.ts` covers `..`), performs zero outbound requests derived from input. No sensitive data found in logs.

## I. Cost Review

Bandwidth ≈ 75% of run cost (D16's worked numbers) — modern-format adoption remains the top lever and is correctly implemented (perceptual per-codec quality; AVIF effort drop above 1920px). Structure protecting cost: bounded variant space (**restored only after C1/H5/H3 fixes**), hybrid generation (compute tracks new assets, not traffic), derivatives deliberately un-tiered vs originals tiered to IA@30d/Glacier-IR@180d, staging hard-expiry, multipart-abort rule, 1-week–3-month log retention on app log groups. Cost risks found: C1 is an _unbounded, attacker-controlled_ cost vector (storage + Lambda + cache dilution); H3/H5 silently multiply storage and misses; L10 (RDS logs) is the one infinite-retention path; L6's fix (CloudFront standard logs) adds modest cost — put them in a lifecycle-expired bucket; M3 can spike RDS into a larger instance class under backlog; 3008MB generator memory is unmeasured (14.7) — power tuning typically pays for itself; no storage-growth metric (L11) means the cost dashboard is blind to its largest slow variable. SQS/CloudWatch/Route53 are noise-level at the design's scale.

### Critical

- **C1 — unbounded variant space.** Closed at both layers the audit named, and at a third it did not. The edge now returns 400 for any viewer path beginning with a storage prefix (`derived/`, `original/`, `master/`, `staging/`), so the normalizer cannot be skipped. `parseVariantName` now rejects any width off the ladder, any height the ratio quantizer cannot produce (`isQuantizedHeight`), and any background off the channel grid. Cross-checked exhaustively: every one of the 40,100 heights the producer can emit is accepted, and an 879k-query fuzz through the committed edge function found zero edge/core disagreements and zero rejections of edge-emitted keys. A composition gate now asserts, for every conformance vector, that a key the edge emits is a key the generator accepts.
- **C2 — superseded originals destroyed early.** `AssetVersion.supersededAt` added, stamped inside the same transaction that writes the successor, with a migration that backfills from the successor's `created_at`. The reclamation query ages off that column; a NULL never matches, so an unknown supersession moment is unreclaimable. **The new test was verified to fail under the old semantics** — a year-old source superseded yesterday was deleted by the previous code and survives under the new.
- **C3 — migration task could not run.** `prisma` is now a production dependency of `@imgopt/db`, the image carries `prisma/`, `prisma.config.ts` and a `scripts/migrate.mjs` entry point that composes `DATABASE_URL` in-process (so the password stays out of the task definition) and propagates the child's exit code. Verified by running the exact task command inside the built image against a fresh database. OpenSSL is now installed in the runtime stage, removing a warning that was one base-image bump from becoming a failure.
- **C4 — control plane served plain HTTP.** A regional certificate stack is created for `apiHost` and wired into the compute stack; the listener terminates TLS 1.2+ (`RECOMMENDED_TLS`) with an 80→443 redirect, Route 53 alias records are created when the zone is ours, and **production synthesis now fails** when no certificate is resolvable. Staging may still run without one so a first deploy is possible before DNS exists.

### High

- **H1 — signed delivery.** The edge normalizes `/p/*` into the same `derived/` key space, and the prefix is now one constant in `packages/core` that the edge, the control plane and the CDN stack all read. One caveat is recorded rather than hidden: the normalizer drops the query string, which carries the signature parameters — safe only because CloudFront validates a trusted key group _before_ invoking a viewer-request function. That ordering cannot be verified without a distribution, so **task 11.6 is not done until a signed URL returns 200 on staging**.
- **H2 — cache-hit alarm could never fire.** `CfnMonitoringSubscription` added to the CDN stack.
- **H3 — focal crop was a no-op.** `focal` removed from the URL grammar, from the render path, and from the API's reprocess trigger. The stored focal point remains as advisory metadata, documented as such in the spec, the schema, and the API reference.
- **H4 — alarm gaps.** Added: generator `Throttles`, `Errors` on all three functions, a CloudFront `5xxErrorRate` alarm, a zero-healthy-targets alarm (the existing one cannot fire when no targets are registered), and a maintenance **heartbeat** on a new `MaintenanceRuns` metric — the one alarm in the stack that fires on _absence_, with its period sized to CloudWatch's one-day evaluation cap.
- **H5 — grammar fragmentation.** `pad` collapses to `contain` at parse time; `outside` is no longer a cropping fit, so gravity is elided from its keys.
- **H6 — originals had no safety net.** Bucket versioning enabled with bounded noncurrent expiry. The interaction that mattered most: `staging/` has its own one-day noncurrent rule, because without it versioning would silently convert the untrusted-byte expiry — and the malware quarantine handler's delete — into a retention policy for exactly those bytes.

### Medium and low

All addressed. The ones with consequences worth naming: **M12** oversize rejections were being metered as `unsupported_format`, corrupting the dimension that separates a client bug from an attack; **M5** ESM bundles emitted to bare `.js` would have failed at init on every invocation; **M16** the SVG flag now fails configuration loading rather than rejecting uploads with a message that blames the uploader; **L4** read endpoints now require a `read` permission, so a key with none can no longer enumerate the catalogue. Spec and design edits reconcile M13, M14, M15, M17, L13 and the 403/400 diagrams with what the code does.

### Found during remediation, not by the audit

1. **Environment booleans were coerced, not parsed.** `z.coerce.boolean()` is `Boolean(value)`, and every environment variable is a string — so `"false"` parsed as **true**. The CDK writes these values literally, which made it concrete: a deployment with scanning off announced `UPLOAD_MALWARE_SCAN_ENABLED=false`, the app read it as _enabled_, and fail-closed would then have held **every upload forever** waiting on a scanner that was never provisioned. `MAINTENANCE_DRY_RUN=false` likewise produced a reclamation job that never deleted. `.env.example` documents both of those exact spellings. Now parsed by spelling, with an unrecognized value failing the process.
2. **The `.mjs` fix uncovered a second init failure.** sharp ships in a layer, which Lambda exposes through `NODE_PATH` — a CommonJS mechanism the ESM resolver ignores entirely. Renaming the bundles would have replaced one init-time crash with another. The bundles now resolve sharp through `createRequire`; a CI step loads each bundle with a layer mounted where Lambda puts one.
3. **`background` was an unbounded key axis.** Full 8-bit hex is 2²⁴ keys per box — 2³² with alpha — each a Sharp invocation and a permanent object, reachable from an ordinary URL. Exactly C1's hole, spelled in hex. Channels now snap to the 4-bit grid, which leaves three-digit shorthand untouched.

Also fixed in passing: the X-Ray sidecar was pinned to `:latest`, found by a test written for M7.
